# Учебная база «Контора»

Кученков Максим Николаевич, группа 4-1ИС. Пример из методических материалов: MySQL, модель в MySQL Workbench, приложение на Node.js и Express. Имя базы `kont4_1is_kuchenkov` записано латиницей, цифрами и подчёркиваниями согласно инструкции.

Для подготовки к защите откройте [памятку](ПАМЯТКА_ДЛЯ_ЗАЩИТЫ.md): в ней кратко объяснены база, API, HTTP-методы и строки кода.

## Файлы проекта

- `01_schema.sql` создаёт базу и таблицы; `02_data.sql` заполняет их примерами. Оба файла нужны, чтобы развернуть пример на новом сервере.
- `03_queries.sql` содержит запросы для проверки и показа в Workbench. Для запуска приложения он необязателен.
- `kuchenkov_4_1is.mwb` — диаграмма и модель Workbench. Файл модели сам по себе не содержит работающий MySQL Server и учебные данные.
- `server.js` — бэкенд; `static/index.html` — страница приложения.
- `package.json` и `package-lock.json` описывают библиотеки Node.js. `node_modules` создаётся командой `npm install` и не загружается в Git.
- `.gitignore` исключает зависимости и локальные файлы из Git.

## База и Workbench

1. Откройте MySQL Workbench и подключитесь к доступному серверу MySQL под своей учётной записью. На учебном компьютере параметры сервера уточните у преподавателя. Адрес `192.168.1.200` в старой методичке относится к её учебной сети; заранее считать его актуальным нельзя.
2. Через **File → Open SQL Script** откройте `01_schema.sql`. Выполните весь файл через **Query → Execute (All or Selection)**, предварительно убрав выделение. Скрипт создаёт новую базу, существующие базы не удаляет. При ошибке создания уточните права или измените имя схемы во всех трёх SQL-файлах и переменной `DB_NAME`.
3. Аналогично выполните `02_data.sql` один раз, затем `03_queries.sql`. Здесь учебные данные из пособия; для платежей и прайса добавлены небольшие примеры. В левой панели обновите **Schemas**, откройте базу и раздел **Tables**.
4. Готовую модель откройте из файла `kuchenkov_4_1is.mwb`. Она построена из этой базы через **Database → Reverse Engineer**. В ней восемь таблиц и их связи. Для сдачи преподаватель может потребовать файл модели, скрипт создания и скриншоты; уточните состав сдачи.
5. При необходимости показать создание сервера из модели: на учебной базе и с разрешённой учётной записью выберите **Database → Forward Engineer**, проверьте выбранную схему и шаги мастера. На существующем сервере не включайте удаление существующих таблиц без необходимости.

Файл модели `.mwb` хранит диаграмму, MySQL Server хранит сами данные. Создание модели через Reverse Engineer восстанавливает структуру из базы. Для показа последовательности, требуемой методичкой, затем можно пройти мастер Forward Engineer на специально выделенной пустой схеме.

## Приложение на Windows

Нужны Node.js версии 18 или новее, доступный MySQL Server и созданная база. В PowerShell из папки проекта:

```powershell
npm install
$env:DB_HOST = '127.0.0.1'
$env:DB_PORT = '3306'
$env:DB_USER = 'root'
$env:DB_NAME = 'kont4_1is_kuchenkov'
$env:DB_PASSWORD = Read-Host 'Пароль MySQL'
npm start
```

Подставьте адрес, порт и пользователя своего сервера. Пароль вводится в консоли и не записывается в файлы проекта. Для локального учебного сервера на этом компьютере порт — `33318`, пользователь — `root`, пароль пустой: вместо `Read-Host` используйте `$env:DB_PASSWORD = ''`. При первом запуске установка библиотек требует доступа к интернету. Откройте в браузере `http://127.0.0.1:5000`. Чтобы остановить сервер, нажмите Ctrl+C в PowerShell.

Все восемь таблиц доступны для просмотра, добавления, изменения и удаления записей. Связанные записи выбираются из списков. Номера в примерах вымышлены. Запись, на которую ссылаются другие данные, MySQL не даст удалить: сначала нужно изменить или удалить связанные записи. Поля составного ключа платежей и состава счетов при изменении зафиксированы; чтобы изменить ключ, удалите запись и создайте новую.

API: `GET /api/tables` возвращает описание таблиц; `GET /api/firms`, `GET /api/firms/1`, `POST /api/firms`, `PUT /api/firms/1`, `DELETE /api/firms/1` показывают операции на предприятиях. Аналогичные пути доступны для `departments`, `staff`, `contracts`, `bills`, `payments`, `prices` и `items`. Для составных ключей номера указываются через запятую: например, `/api/payments/1,2`. Тела POST и PUT — JSON с именами столбцов соответствующей таблицы. GET-списки показывают актуальные данные MySQL.

## Кратко о связях

- Отдел и сотрудники: один ко многим. Сотрудник может быть без отдела, как директор в примере.
- Сотрудник и руководимый отдел: не более одного отдела на сотрудника, у отдела не более одного руководителя. Руководитель может быть назначен позже.
- Предприятие и договоры, сотрудник и договоры, договор и счета: один ко многим.
- Счёт и платежи: один ко многим. Платёж определяется номером счёта и номером платежа внутри счёта.
- Счета и позиции прайса: многие ко многим через `k_protokol`, где хранятся количество и цена в счёте.

В старом приложении к пособию поля отдела и руководителя обязательны одновременно, что мешает первичному заполнению примера; здесь на этапе добавления они допускают NULL. Пособие описывает составной ключ платежа, но его распечатанный SQL содержит только номер платежа; здесь реализован составной ключ. Ограничение UNIQUE для руководителя соответствует связи один к одному. Эти решения можно объяснить на защите.
