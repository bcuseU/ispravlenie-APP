# Памятка для защиты проекта «Контора»

Не нужно заучивать всё слово в слово. Сначала открой приложение и Workbench, затем попробуй объяснить своими словами, что происходит при добавлении предприятия.

## Что делает проект

Можно начать так:

> «Я сделал учебную базу „Контора“ по методическим материалам. В ней хранятся отделы, сотрудники, предприятия, договоры, счета, платежи, прайс-лист и состав счетов. Для базы создана диаграмма в MySQL Workbench. Через веб-приложение можно просматривать, добавлять, изменять и удалять записи».

За что отвечает каждая часть:

- **MySQL Server** хранит таблицы и данные и выполняет SQL-запросы.
- **MySQL Workbench** подключается к серверу. В нём можно смотреть таблицы и запросы, а также открыть диаграмму связей.
- **Фронтенд** — страница `static/index.html`. На ней находятся кнопки, формы и таблицы.
- **Бэкенд** — `server.js` на Node.js. Он принимает HTTP-запросы от страницы, проверяет данные и обращается к MySQL.

## Как части взаимодействуют

Например, пользователь открывает раздел «Предприятия»:

1. Страница отправляет на сервер запрос `GET /api/firms`.
2. Бэкенд получает запрос и определяет, что `firms` соответствует таблице `k_firm`.
3. Бэкенд отправляет в MySQL запрос `SELECT`, получает строки и возвращает их в формате JSON.
4. Страница получает ответ и рисует таблицу.

Если пользователь заполняет форму и нажимает «Добавить», страница отправляет `POST /api/firms` с данными в JSON. Бэкенд проверяет поля, выполняет `INSERT` в MySQL и сообщает странице результат. Она заново запрашивает список.

**API** расшифровывается как *Application Programming Interface* — программный интерфейс приложения. Здесь это набор адресов и правил, по которым фронтенд обращается к бэкенду. Например, `/api/firms` отвечает за предприятия. На фронтенде запрос отправляет JavaScript через `fetch`, на бэкенде его принимает Express. Далее бэкенд обращается к MySQL через библиотеку `mysql2`.

**HTTP** — протокол, по которому браузер и сервер обмениваются запросами и ответами. HTTP-метод показывает, какое действие запрашивается. Данные в ответах передаются в JSON — текстовом формате с полями и значениями.

## CRUD и HTTP-методы

**CRUD** — четыре основные операции с данными: Create, Read, Update, Delete.

| Действие | HTTP-запрос в проекте | Что делает бэкенд |
|---|---|---|
| Create — создать | `POST /api/firms` | Проверяет данные и выполняет `INSERT`. |
| Read — прочитать | `GET /api/firms` или `GET /api/firms/1` | Выполняет `SELECT`: возвращает список или одну запись. |
| Update — изменить | `PUT /api/firms/1` | Проверяет данные и выполняет `UPDATE` для записи с номером 1. |
| Delete — удалить | `DELETE /api/firms/1` | Выполняет `DELETE` для записи с номером 1. |

Вместо `firms` можно указать другой раздел. Например, `staff` — сотрудники, `contracts` — договоры. Для платежей номер счёта и номер платежа вместе образуют ключ; пример адреса: `/api/payments/1,2`.

Успешное создание возвращает статус **201**, успешное чтение, изменение или удаление — **200**. Если записи нет, сервер отвечает **404**. Если удалить связанную запись нельзя, приложение показывает ошибку **409**: сначала нужно разобраться со связанными данными.

## Что я добавил в бэкенд

В `server.js` описаны восемь таблиц и разрешённые поля. Для них сделаны обработчики GET, POST, PUT и DELETE. Бэкенд проверяет обязательные поля, типы и длину значений, а затем выполняет SQL. Значения передаются в запрос отдельно через `?`, а названия таблиц и столбцов берутся из заранее заданного списка. Это помогает не подставлять произвольный ввод пользователя прямо в SQL.

База тоже следит за связями: например, нельзя создать договор с несуществующим предприятием. Если у предприятия есть договоры, удалить предприятие сразу не получится — внешний ключ защищает связанные данные.

## Объяснение десяти строк `server.js`

Ниже выбраны реальные строки файла. Они идут в порядке кода; номера помогут найти их в редакторе.

1. **Строка 1:** `const express = require('express');` — подключаю Express, чтобы принимать HTTP-запросы.
2. **Строка 2:** `const mysql = require('mysql2/promise');` — подключаю библиотеку для работы с MySQL через асинхронные операции.
3. **Строка 3:** `const path = require('path');` — подключаю стандартный модуль Node.js для работы с путями к файлам.
4. **Строка 5:** `const app = express();` — создаю приложение Express.
5. **Строка 6:** `app.use(express.json());` — разрешаю бэкенду разбирать JSON, который приходит в запросе.
6. **Строка 7:** `app.use(express.static(path.join(__dirname, 'static')));` — отдаю браузеру файлы страницы из папки `static`.
7. **Строка 8:** `const db = mysql.createPool({` — создаю пул соединений с базой. Пул позволяет использовать несколько соединений повторно.
8. **Строка 9:** `host: process.env.DB_HOST || '127.0.0.1',` — беру адрес сервера MySQL из настройки; если её нет, использую локальный адрес.
9. **Строка 10:** `port: Number(process.env.DB_PORT || 3306),` — задаю порт MySQL и преобразую его в число. Здесь `3306` — значение по умолчанию; на настроенном учебном сервере этого компьютера используется `33318`.
10. **Строка 13:** `database: process.env.DB_NAME || 'kont4_1is_kuchenkov',` — выбираю имя базы из настройки или использую имя базы проекта.

Следующие полезные места: строки **92–95** обрабатывают получение списка; **100–103** добавляют запись; **104–107** изменяют её; **108–111** удаляют. Там `req` — запрос от браузера, `res` — ответ сервера, `async` и `await` позволяют дождаться результата MySQL.

## Связи на диаграмме

- **Один ко многим:** у отдела может быть несколько сотрудников; один сотрудник относится не более чем к одному отделу. У предприятия может быть несколько договоров, у договора — несколько счетов.
- **Один к одному:** у отдела не более одного руководителя, и один сотрудник может руководить не более чем одним отделом. Руководитель может быть пока не назначен.
- **Многие ко многим:** в счёте может быть несколько товаров или услуг, а одна позиция прайса может встречаться в нескольких счетах. Для этого есть промежуточная таблица `k_protokol`.
- **Первичный ключ (PK)** отличает одну строку таблицы от другой. **Внешний ключ (FK)** ссылается на связанную запись другой таблицы.

## Что показать

1. В Workbench открыть `kuchenkov_4_1is.mwb` и объяснить связи на диаграмме. Модель `.mwb` хранит структуру и диаграмму; данные хранятся в MySQL Server.
2. В приложении открыть «Предприятия», добавить учебное предприятие с телефоном, затем изменить его.
3. В Workbench выполнить запрос к `k_firm` и показать, что запись появилась в базе. Обновить результат после изменения.
4. Удалить добавленное предприятие и объяснить, что это запрос DELETE. Для связанных записей MySQL может запретить удаление.

Пошаговый запуск базы и приложения на другом компьютере описан в `README.md`. Все приведённые телефоны — учебные.
